# 1. 테스트 목적

이 문서는 SmallWorking이 REQUIREMENTS에서 정의한 기능을 **제대로 구현했는지 확인하는 방법**을 정의한다.

```text
REQ-xxx  (무엇을 해야 하는가)
   ↓
API-xxx / COMP-xxx  (어떻게 구현하는가)
   ↓
TC-xxx  (제대로 만들어졌는가)   ← 현재 문서
```

각 테스트 케이스는 Requirement ID와 연결되며, Claude Code가 기능을 구현하거나 수정할 때 **관련 테스트를 먼저 확인하는 기준**이 된다.

> 테스트 도구는 구현 단계에서 확정하고 TRD 또는 Claude.md에 반영한다.

# 4. 테스트 결과 상태

| 상태 | 의미 |
|---|---|
| `Not Run` | 아직 실행하지 않음 |
| `Pass` | 기대 결과와 일치 |
| `Fail` | 기대 결과와 불일치 |
| `Blocked` | 선행 기능 미구현 등으로 실행 불가 |
| `Pending Policy` | **정책(TBD)이 확정되지 않아 기대 결과를 확정할 수 없음** |

> `Pending Policy` 테스트는 결과를 억지로 확정하지 않는다. 정책이 확정되면 기대 결과를 채우고 `Not Run`으로 바꾼다.

**우선순위:** `P1` 핵심 기능(반드시 통과) / `P2` 중요 / `P3` 보조

# 19. Definition of Done

기능 하나가 "완료"되려면 다음을 모두 만족해야 한다.

1. 관련 REQ의 **P1 테스트가 모두 `Pass`**이다.
2. Backend API 테스트가 자동화되어 있고 통과한다.
3. Frontend Validation과 **Backend Validation이 모두** 동작한다.
4. 관련 보안 테스트(TC-SEC)를 통과한다.
5. Mobile(360px)에서 가로 스크롤 없이 동작한다.
6. `Pending Policy` 테스트는 정책 확정 후 기대 결과를 갱신했다.
7. 명세(API_SPEC / COMPONENT_SPEC)와 구현이 일치한다. 다르면 명세를 먼저 수정한다.
