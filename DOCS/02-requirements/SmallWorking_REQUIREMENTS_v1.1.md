## 1. 문서 목적

본 문서는 SmallWorking PRD v1.0에 정의된 제품 목표와 기능 범위를 실제 개발 가능한 수준의 **검증 가능한 요구사항(Requirement)** 으로 구체화한다.

각 요구사항은 이후 다음 문서와 연결한다.

```text
PRD
 ↓
REQUIREMENTS
 ↓
TRD / DATA_MODEL / API_SPEC / COMPONENT_SPEC
 ↓
TEST_CASES
 ↓
Implementation
```

요구사항 ID는 이후 설계 및 테스트에서 추적할 수 있도록 고유하게 부여한다.

# 2. 사용자 및 권한 요구사항

## REQ-001. 관리자 역할

시스템은 콘텐츠와 사이트를 관리할 수 있는 관리자 역할을 제공해야 한다.

관리자는 다음 작업을 수행할 수 있어야 한다.

- 게시물 등록
- 게시물 조회
- 게시물 수정
- 게시물 삭제
- 카테고리 등록
- 카테고리 수정
- 카테고리 삭제
- 카테고리 순서 변경
- 댓글 관리

---

## REQ-002. 방문자 역할

방문자는 별도의 회원가입이나 로그인 없이 공개 콘텐츠를 이용할 수 있어야 한다.

방문자는 다음 작업을 수행할 수 있어야 한다.

- 홈페이지 조회
- 카테고리 조회
- 게시물 조회
- 게시물 좋아요
- 댓글 작성
- 댓글 수정
- 댓글 삭제
- 댓글에 대한 답글 작성

---

## REQ-003. 방문자 회원가입 제외

시스템은 v1.0에서 방문자 회원가입 기능을 제공하지 않아야 한다.

다음 기능은 초기 범위에서 제외한다.

- 회원가입
- 방문자 로그인
- 방문자 프로필
- 친구/팔로우
- 개인 메시지

---

# 3. 홈페이지 요구사항

## REQ-004. 홈페이지 기본 구성

홈페이지는 SmallWorking의 주요 콘텐츠 영역을 한 화면에서 탐색할 수 있도록 구성해야 한다.

홈페이지에는 최소한 다음 정보가 제공되어야 한다.

- 전체 카테고리
- 카테고리별 최신 게시물
- 전체 최신 게시물
- 인기 게시물

---

## REQ-005. 카테고리별 최신 게시물

홈페이지는 각 카테고리 영역마다 해당 카테고리에 등록된 최신 게시물 일부를 표시해야 한다.

최신 게시물은 게시물 등록일을 기준으로 최신순으로 판단한다.

---

## REQ-006. 전체 최신 게시물

홈페이지는 모든 카테고리의 게시물을 대상으로 최신 게시물 목록을 제공해야 한다.

최신순의 기준은 게시물 등록일이다.

---

## REQ-007. 인기 게시물

홈페이지는 게시물의 좋아요 수를 기준으로 인기 게시물을 제공해야 한다.

좋아요 수가 많은 게시물이 우선적으로 표시되어야 한다.

인기 게시물의 정확한 표시 개수와 기간 조건은 후속 설계 단계에서 확정한다.

> **[v1.1 확정]** 홈 인기 게시물은 **5개**, 집계 기간은 **전체 기간**이다. 좋아요 수가 같으면 최근 게시물을 먼저 표시한다 (DEC-006). 카테고리별 최신 게시물은 **3개**, 전체 최신 게시물은 **5개**를 표시한다.

---

## REQ-008. 카테고리 자동 반영

관리자가 새로운 카테고리를 추가하면 홈페이지의 카테고리 영역에도 해당 카테고리가 자동으로 반영되어야 한다.

홈페이지의 카테고리 구성을 소스 코드 수정 없이 관리할 수 있어야 한다.

---

# 4. 카테고리 요구사항

## REQ-009. 기본 카테고리

v1.0에서는 다음 카테고리를 기본으로 제공한다.

- DIY
- Portfolio
- Blog
- Board

---

## REQ-010. 카테고리 추가

관리자는 새로운 카테고리를 추가할 수 있어야 한다.

카테고리 추가 시 최소한 카테고리 이름을 지정할 수 있어야 한다.

---

## REQ-011. 카테고리 수정

관리자는 기존 카테고리의 정보를 수정할 수 있어야 한다.

---

## REQ-012. 카테고리 삭제

관리자는 기존 카테고리를 삭제할 수 있어야 한다.

카테고리에 이미 게시물이 존재하는 경우의 처리 방식은 데이터 모델 및 관리 정책 설계 단계에서 확정한다.

> **[v1.1 확정]** 게시물이 1개 이상 있는 카테고리는 **삭제할 수 없다**. 관리자는 게시물을 다른 카테고리로 옮기거나 삭제한 뒤 카테고리를 삭제한다 (DEC-005).

---

## REQ-013. 카테고리 순서 관리

관리자는 카테고리가 표시되는 순서를 변경할 수 있어야 한다.

변경된 순서는 홈페이지 및 카테고리 메뉴에 반영되어야 한다.

---

# 5. 게시물 요구사항

## REQ-014. 게시물 등록

관리자는 게시물을 등록할 수 있어야 한다.

게시물은 최소한 다음 정보를 포함해야 한다.

- 제목
- 카테고리
- 본문
- 등록일
- 수정일

---

## REQ-015. 게시물 카테고리 지정

게시물은 하나의 카테고리에 속해야 한다.

게시물 등록 또는 수정 시 관리자는 카테고리를 선택할 수 있어야 한다.

---

## REQ-016. 게시물 수정

관리자는 기존 게시물의 내용을 수정할 수 있어야 한다.

게시물 수정 시 수정일이 갱신되어야 한다.

---

## REQ-017. 게시물 삭제

관리자는 기존 게시물을 삭제할 수 있어야 한다.

게시물 삭제 시 해당 게시물과 연결된 데이터의 처리 방식은 데이터 모델 설계 단계에서 정의한다.

> **[v1.1 확정]** 게시물을 삭제하면 해당 게시물의 이미지(파일 포함), 댓글과 답글, 좋아요 기록을 **함께 삭제**한다. 삭제 전에 확인 절차를 거친다 (DEC-005).

---

## REQ-018. 게시물 본문 이미지

게시물 본문에는 이미지를 삽입할 수 있어야 한다.

이미지는 본문의 특정 위치에 삽입할 수 있어야 하며, 본문 마지막에만 별도로 첨부되는 방식으로 제한하지 않는다.

---

## REQ-019. 게시물 이미지 순서

게시물에 여러 이미지가 포함된 경우 이미지가 본문에 지정된 순서대로 표시되어야 한다.

---

## REQ-020. 게시물 이미지 개수

게시물 하나에 약 20개 수준의 이미지를 등록할 수 있도록 지원해야 한다.

정확한 최대 허용 개수는 구현 및 저장 방식 검토 후 확정한다.

> **[v1.1 확정]** 게시물당 최대 **20장**. 이미지 1장은 최대 **10MB**, 허용 형식은 **jpg, png, webp, gif**이다 (DEC-002).

---

## REQ-021. 동영상 업로드 제외

v1.0에서는 게시물 동영상 직접 업로드 기능을 제공하지 않는다.

---

# 6. 게시물 조회 요구사항

## REQ-022. 게시물 상세 조회

방문자는 게시물의 상세 내용을 조회할 수 있어야 한다.

상세 화면에는 최소한 다음 정보가 제공되어야 한다.

- 제목
- 카테고리
- 본문
- 이미지
- 등록일
- 수정일
- 좋아요 수
- 댓글
- 답글

---

## REQ-023. 카테고리 게시물 목록

방문자는 특정 카테고리에 속한 게시물 목록을 조회할 수 있어야 한다.

게시물 목록은 기본적으로 최신 게시물이 먼저 표시되어야 한다.

---

# 7. 댓글 요구사항

## REQ-024. 댓글 작성

방문자는 회원가입이나 로그인 없이 게시물에 댓글을 작성할 수 있어야 한다.

댓글 작성 시 최소한 다음 정보를 입력해야 한다.

- 닉네임
- 비밀번호
- 댓글 내용

---

## REQ-025. 댓글 표시

게시물 상세 화면에서 해당 게시물에 등록된 댓글을 확인할 수 있어야 한다.

댓글은 작성 순서 또는 관리 가능한 정렬 기준에 따라 표시할 수 있어야 하며, 구체적인 정렬 방식은 후속 설계에서 확정한다.

> **[v1.1 확정]** 댓글과 답글은 모두 **작성순**(오래된 것이 위)으로 표시하며, v1.0에서는 페이지를 나누지 않고 전체를 표시한다 (DEC-006).
>
> **[v1.1 확정]** 답글이 달린 댓글을 삭제하면 **"삭제된 댓글입니다"**로 표시하고 답글은 유지한다 (DEC-005, REQ-027 관련).

---

## REQ-026. 댓글 수정

댓글 작성자는 자신이 작성한 댓글을 수정할 수 있어야 한다.

댓글 수정 시 작성 당시 입력한 비밀번호를 이용하여 본인 여부를 확인해야 한다.

---

## REQ-027. 댓글 삭제

댓글 작성자는 자신이 작성한 댓글을 삭제할 수 있어야 한다.

댓글 삭제 시 작성 당시 입력한 비밀번호를 이용하여 본인 여부를 확인해야 한다.

---

## REQ-028. 답글 작성

방문자는 기존 댓글에 답글을 작성할 수 있어야 한다.

답글 작성에도 댓글과 동일하게 닉네임과 비밀번호를 사용할 수 있어야 한다.

---

## REQ-029. 답글 깊이 제한

답글은 1단계까지만 지원해야 한다.

허용되는 구조:

```text
댓글
 └─ 답글
```

다음과 같은 다단계 구조는 지원하지 않는다.

```text
댓글
 └─ 답글
     └─ 답글
         └─ 답글
```

---

# 8. 좋아요 요구사항

## REQ-030. 게시물 좋아요

방문자는 게시물에 좋아요를 표시할 수 있어야 한다.

좋아요 수는 게시물별로 집계되어야 한다.

---

## REQ-031. 댓글 좋아요 제외

v1.0에서는 댓글에 대한 좋아요 기능을 제공하지 않는다.

---

## REQ-032. 중복 좋아요 정책

동일 방문자가 동일 게시물에 여러 번 좋아요를 증가시킬 수 있는지 여부와 중복 방지 방식은 후속 보안 및 데이터 설계 단계에서 확정한다.

> **[v1.1 확정]** 같은 브라우저는 같은 게시물에 **좋아요를 1회만** 할 수 있다. 다시 누르면 **좋아요가 취소**된다. 방문자는 브라우저 쿠키의 무작위 식별값으로 구분하며, 회원가입이나 로그인은 요구하지 않는다 (DEC-004).

---

# 9. 관리자 콘텐츠 관리 요구사항

## REQ-033. 게시물 관리

관리자는 관리자 영역에서 게시물 목록을 확인하고 게시물을 등록·수정·삭제할 수 있어야 한다.

---

## REQ-034. 카테고리 관리

관리자는 관리자 영역에서 카테고리를 등록·수정·삭제하고 표시 순서를 변경할 수 있어야 한다.

---

## REQ-035. 댓글 관리

관리자는 관리자 영역에서 등록된 댓글을 조회하고 관리할 수 있어야 한다.

댓글 관리에는 최소한 부적절한 댓글을 삭제할 수 있는 기능이 포함되어야 한다.

---

# 10. 반응형 요구사항

## REQ-036. 반응형 웹

웹사이트는 다음 환경에서 정상적으로 이용할 수 있어야 한다.

- Desktop
- Tablet
- Mobile

화면 크기가 변경되어도 주요 콘텐츠를 이용하는 데 문제가 없어야 한다.

---

## REQ-037. 모바일 콘텐츠 표시

모바일 환경에서는 게시물 본문, 이미지, 댓글 등의 콘텐츠가 화면 너비를 벗어나지 않도록 표시되어야 한다.

---

# 11. 기본 입력 및 데이터 검증 요구사항

## REQ-038. 필수 입력 검증

게시물, 카테고리, 댓글 등 입력이 필요한 기능은 필수 항목이 누락된 경우 저장되지 않아야 한다.

---

## REQ-039. 입력값 검증

사용자가 입력한 데이터는 서버 또는 데이터 저장 계층에서 적절하게 검증되어야 한다.

특히 다음 항목은 기본적인 유효성 검증이 필요하다.

- 제목
- 카테고리
- 닉네임
- 비밀번호
- 댓글 내용
- 게시물 본문

구체적인 길이 제한과 허용 문자는 후속 설계 단계에서 확정한다.

> **[v1.1 확정]** 입력값은 앞뒤 공백을 제거한 뒤 다음 길이로 검증한다 (DEC-006).
>
> | 항목 | 길이 |
> |---|---|
> | 게시물 제목 | 1~200자 |
> | 카테고리 이름 | 1~30자 (중복 불가) |
> | 카테고리 설명 | 0~200자 |
> | 댓글 닉네임 | 2~20자 |
> | 댓글 비밀번호 | 4~64자 |
> | 댓글 내용 | 1~1,000자 |

---

# 12. 오류 처리 요구사항

## REQ-040. 존재하지 않는 콘텐츠 처리

존재하지 않는 게시물이나 카테고리를 요청한 경우 사용자가 오류 원인을 이해할 수 있는 적절한 화면 또는 메시지를 제공해야 한다.

---

## REQ-041. 작업 실패 처리

게시물 등록·수정·삭제, 댓글 등록·수정·삭제 등의 작업이 실패한 경우 사용자가 작업 실패를 인지할 수 있어야 한다.

# 13. 보안 기본 요구사항

## REQ-042. 관리자 기능 보호

관리자 기능은 일반 방문자가 임의로 접근하여 사용할 수 없도록 보호되어야 한다.

관리자 인증 방식은 TRD 및 보안 설계 단계에서 확정한다.

> **[v1.1 확정]** 관리자는 아이디와 비밀번호로 로그인하며, 서버 세션으로 인증 상태를 유지한다. 2시간 동안 활동이 없거나 로그인 후 7일이 지나면 다시 로그인해야 하고, 5회 연속 실패하면 10분 동안 로그인할 수 없다 (DEC-003).

---

## REQ-043. 댓글 비밀번호 보호

댓글 수정 및 삭제에 사용되는 비밀번호는 평문으로 저장하지 않아야 한다.

비밀번호 저장 및 검증 방식은 TRD/DATA_MODEL 단계에서 확정한다.

> **[v1.1 확정]** 댓글 비밀번호와 관리자 비밀번호는 **Argon2 해시**로만 저장하며, 어떤 응답에도 비밀번호나 해시를 포함하지 않는다 (DEC-003).

---

## REQ-044. 사용자 입력 콘텐츠 보호

게시물 본문과 댓글 등 방문자가 입력할 수 있는 콘텐츠는 악의적인 스크립트가 실행되지 않도록 처리해야 한다.

> **[v1.1 확정]** 게시물 본문은 허용된 서식 요소만 저장·표시하고(DEC-001), 댓글은 일반 텍스트로만 표시한다.

# 16. 요구사항 추적성

요구사항은 이후 설계 및 테스트 문서와 연결한다.

예:

```text
PRD
 │
 └─ REQ-018 게시물 본문 이미지
       │
       ├─ DATA-xxx 이미지 데이터 구조
       ├─ API-xxx 이미지 등록 API
       ├─ COMP-xxx 게시물 에디터
       └─ TEST-xxx 이미지 삽입/표시 테스트
```

향후 모든 핵심 기능은 가능한 한 다음 구조로 추적한다.

```text
PRD → REQ → DATA / API / COMPONENT → TEST → CODE
```

# 17. 요구사항 작성 원칙

본 문서의 요구사항은 다음 원칙을 따른다.

1. 하나의 요구사항은 가능한 한 하나의 기능 또는 조건을 설명한다.
2. 각 요구사항은 테스트 가능해야 한다.
3. 구현 기술을 불필요하게 요구사항에 포함하지 않는다.
4. 구현 방법과 요구사항을 분리한다.
5. 아직 결정되지 않은 사항은 임의로 확정하지 않는다.
6. PRD의 범위를 벗어나는 기능은 추가하지 않는다.
7. 새로운 기능이 추가되면 먼저 REQUIREMENTS를 갱신한 후 설계 문서를 갱신한다.
